# Mascon: EasyEDA Pro から KiCad 8 への変換メモ

- 変換元: `ProPrj_Mascon_2026-09-23.epro2`（EasyEDA Pro / 嘉立創EDA専業版 v3.2）
- 変換スクリプト: `../convert_epro2.py`（再エクスポートしたときは再実行してください）
- 検証スクリプト: `../verify_kicad_output.py`（KiCad なしで構文、個数、ネットを照合します）
- 変換先の形式: KiCad 8.0（pcb/mod は `20240108`、sch/sym は `20231120`）

```
python3 convert_epro2.py ProPrj_Mascon_2026-09-23.epro2 kicad_output
python3 verify_kicad_output.py kicad_output Mascon
```

> **注意:** この環境には KiCad がインストールされていません。そのため、KiCad の GUI で実際に開いて確認する作業はまだ行っていません。
> 検証はテキスト解析と独立したロジックによるネット照合だけです。最初に KiCad で開いたときに、下の「手動で確認・修正すべき点」を実施してください。

## 出力ファイル

| ファイル | 内容 |
|---|---|
| `Mascon.kicad_pro` | 最小構成のプロジェクトファイル（Default ネットクラスのみ） |
| `sym-lib-table` / `fp-lib-table` | プロジェクトローカルのライブラリ設定（ニックネーム `Mascon`, `${KIPRJMOD}` 相対） |
| `Mascon.kicad_sym` | シンボルライブラリ（10 個）。回路図で使用中の 6 個に加え、ライブラリにあるだけの未使用部品 4 個（PTD904、Res_0603、PZ254V-11-04P、M3 ネジ）を含みます |
| `Mascon.kicad_footprints.pretty/` | フットプリントライブラリ（8 個、下表） |
| `Mascon.kicad_sch` | 回路図 1 枚（A4）。シンボル 17 個（部品 7 個＋電源シンボル 10 個）、ワイヤー 25 本 |
| `Mascon.kicad_pcb` | 4 層基板（80 × 45 mm）。フットプリント 7 個、配線 62 本、円弧配線 2 本、ゾーン 2 つ |

## 問題なく変換できたもの

- **部品配置**: 基板上の座標、回転、リファレンス（H1, H2, H3, U1–U3, VR1）はすべて元データどおりです。
- **パッド**: 形状は rect / circle / oval / custom（ポリゴン）に対応しています。穴径、スルーホールか SMD か、パッド角度も反映しています。
- **ネット**: `PAD_NET` をそのまま使っています（`VCC`, `GND`, `$1N9`, `$1N14`, `$1N15`, `$1N16`, `$1N21`, `$1N22`）。
- **配線**: 表面と裏面の配線 62 本、円弧配線 2 本の層とネットを保持しています。回避用の円弧の向きもパッドとの位置関係から確認済みです。
- **基板外形**: 矩形 80 × 45 mm と取付穴 4 つ（φ4.4 mm の Edge.Cuts 円）です。
- **層構成**: 表面、In1.Cu（GND プレーン）、In2.Cu（VCC プレーン）、裏面の 4 層です。
- **回路図**: 部品の配置と回転、ワイヤー、GND/VCC の電源シンボル（KiCad の power シンボルとして作成）を変換しています。
- **シンボルのフィールド**: フットプリント（`Mascon:...`）、データシート、MPN、LCSC 番号をシンボルのフィールドに入れています。
- **回路図と基板の対応付け**: 各フットプリントの `(path)` を回路図シンボルの UUID に合わせてあります。そのため「回路図から PCB を更新」で既存の部品として扱われます。
- **シルク印刷**: テキスト 6 つとロゴ（電車アイコン、表裏）を変換しています。ロゴは穴付きポリゴンを切れ込み（keyhole）でつないだ塗りつぶし図形です。

## 近似したもの、または省略したもの

1. **内層プレーン（GND/VCC）**
   - 基板外形いっぱいの KiCad ゾーンとして作り直しています。塗りつぶし結果は保存していないので、開いたら `B`（全ゾーンを再塗りつぶし）を押してください。
   - クリアランス 0.3 mm とサーマル 0.5 mm は仮の値です。EasyEDA 側の値ではありません。
2. **シルクのテキスト**
   - 元は TrueType（Google Sans）です。KiCad では標準のストロークフォントを使い、元の fontSize × 0.7 の大きさにしています。
   - 位置や幅は目安です。裏面のテキストは `mirror` を付けていますが、左右どちら向きに伸びるかは未確認です。
3. **3D モデル**: 変換していません（EasyEDA のモデル ID しかないため）。
4. **デザインルール**: RULE / RULE_SELECTOR は移していません。KiCad の既定値（クリアランス 0.2 mm、配線幅 0.254 mm など）になっています。
   - EasyEDA ではソルダーマスクの拡張が 2 mil でした。KiCad 側は 0 です。
5. **FILL（層 50/51）**: ピンのはんだ付け範囲を表す補助図形で、パッドと重複するため省略しました。
6. **層 48/49 の図形**: 部品外形と 1 ピン目の印です。F.Fab に置いています。
7. **SMD_BD5.5-D3.9 の多層 FILL**: NPTH 穴として近似しています（未配置の部品です）。
8. **回路図の図枠（Drawing-Symbol_A4）**: シンボルとしては配置していません。KiCad 標準の A4 図枠とタイトル欄（タイトル「Mascon」、日付、版 V1.0）に置き換えています。
9. **孤立したワイヤー線分 7 本**: WIRE レコードが存在しない LINE 群です。EasyEDA 上で削除されたワイヤーの残骸と判断して捨てました。
   - これらはどのピンにもつながっていません。捨てた後のネットは基板の PAD_NET と完全に一致しています。
10. **削除済みオブジェクト**: 本体が空のレコード（PAD_NET 110 件、LINE 41 件など）は削除済みとして無視しています。

## 手動で確認・修正すべき点

1. **ゾーンを再塗りつぶしして DRC を実行する**: PCB を開いて `B` を押し、DRC を実行してください。
   - GND/VCC のスルーホールは内層プレーンだけでつながっています。塗りつぶすまでは「未配線」と表示されます。
2. **ERC の警告を確認する**。次の警告が出る見込みです。
   - 未接続ピン: H1 の全ピン（RP2040 モジュールを機械的に固定するだけ）、H2 の未使用ピン、VR1 の 4–6 ピン（2 連の片側）、U1–U3 の 1 と 4 ピン。
     元データに未接続フラグ（No Connect）がないためです。意図どおりなら No Connect フラグを置いてください。
   - GND/VCC が「電源出力に駆動されていない」: 必要なら `PWR_FLAG` を追加してください。
   - FSM101 と 17 ピンヘッダーのピン種別は元データで Undefined でした。そのため KiCad では `unspecified` になっています。
3. **ネット名**: 自動ネットは EasyEDA の名前（`$1N9` など）のまま基板に書いています。回路図にはラベルがありません。
   - 「回路図から PCB を更新」を実行すると、KiCad が `Net-(H2-Pad6)` 形式に名前を変えることがあります。つながり自体は変わりません。
4. **フットプリントを目視で確認する**。
   - VR1（基板取付用2連ボリューム）: 1 ピン（角パッド）の位置と、シルク枠が基板の左端にはみ出していないかを見てください（元データでも枠は x=0 付近）。
   - H3（OLED）: 27.3 mm 角のシルク枠とピン順（1 GND, 2 VCC, 3, 4）。
5. **裏面のシルク**: 「Train Mascon」「V1.0 ©2026 Yu Sato」と電車ロゴの位置と向きを 3D ビューアで確認してください。
6. **基板の厚さ**: EasyEDA の積層の合計は約 1.59 mm です。KiCad 側は 1.6 mm にしてあり、詳しい積層は設定していません。発注前に基板設定で確認してください。

## 解析した EasyEDA Pro 形式の仕様と確信度

| 項目 | 内容 | 確信度 |
|---|---|---|
| 行の形式 | `{header}||{body}|`。本体が空なら削除済み、DOCHEAD でサブドキュメントが切り替わる | 高 |
| 部品とライブラリの対応 | 部品の子 ATTR の `Symbol` / `Device` / `Footprint` で対応付く。部品側の Footprint 属性が DEVICE より優先（H3 の OLED で確認）。`partId` は同じシンボル内の PART（ユニット）を選ぶだけ | 高 |
| 回路図の座標 | 1 単位 = 10 mil、Y 軸は下向き、回転は見た目で反時計回り。PIN の (x,y) が接続点。ワイヤー端点との一致数で 2 通りの仮説を比べて確定 | 高 |
| PCB とフットプリントの座標 | mil 単位、Y 軸は上向き、角度は反時計回り。配線端点とパッド位置、PAD_NET のネットが全部一致することで確認 | 高 |
| 円弧 `["ARC", 角度, x, y]` | 角度は反時計回りが正（Y 上向き）。パッドを避ける向きになることで確認 | 中〜高 |
| 矩形 `["R", x, y, w, h, r]` | (x, y) が左上で、y−h まで伸びる（Y 上向き） | 高 |
| ポリゴンパッドの座標 | フットプリント上の絶対座標 | 高 |
| LAYER_FILL | プレーンの計算済み塗りつぶし（円弧の角度は 0.1° 単位らしい）。ネット名と層だけを使用 | 中 |
| IMAGE | 元図形は Y 上向き。バウンディングボックスを width/height に合わせて拡大縮小 | 中 |
| パッドの角度と width/height | width は回転前の X 方向の寸法 | 中（この基板では正方形か円のパッドばかりで影響なし） |

## 検証結果（verify_kicad_output.py）

- **構文**: 生成したファイル 13 個（sch, pcb, sym, lib-table 2 つ, kicad_mod 8 つ）が、厳密な S 式パーサで解析できることを確認しました。
- **回路図**: 17 シンボル、25 ワイヤー。宙に浮いたワイヤー端は 0 です。
  - KiCad の座標の扱い（ライブラリは Y 上向き、回転は反時計回り）に従ってピン位置を計算し直しました。複数ピンのネットは 8 個でした。
- **基板**: フットプリント 7、パッド 56（元データとすべての部品で一致）、ネット 8、配線 62、円弧 2、ゾーン 2、Edge.Cuts 5。
- **回路図と基板の照合**: 複数ピンのネット 8 個が完全に一致しました（PASS）。
- **配線の照合**: 配線で結ぶ 6 ネットは、KiCad の座標の扱いで計算したパッド位置に配線がつながり、ネットごとに 1 つにまとまることを確認しました。
  - 別ネットのパッドに乗っている配線端は 0 です。GND/VCC は内層ゾーンでつながります。
